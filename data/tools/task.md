Hands one self-contained job to a subagent: another crowbot, with tools of its own, that works through it and replies once. Its reply is this call's result; the user does not see it, so tell them what matters from it. Use it for work whose steps you do not need to watch, such as a broad search across the project, to keep your own context for the task in hand. The subagent knows nothing of this conversation: put everything it needs in `prompt`, and say what its reply should hold. Calls in the same reply run at the same time; each subagent that can change files is told the others' jobs and scopes. Give every subagent that changes files a `scope` of the paths it may change, not overlapping another's. A scope is where it starts, not a wall: if the job needs a file outside it, the subagent claims that file itself with `claim` (granted unless another running subagent holds it), so a job that touches a few files beyond its scope is fine to hand over as it is. You yourself cannot change a running subagent's files until it finishes.

Hand over the job, not your reading of it: don't read or search the files a subagent will work on first, since it reads them itself and your reading is spent twice. Look only at what you need to write its `prompt`. Each kind runs on the model the user set for it; name a `model` only when the job clearly needs a stronger or a cheaper one than that.
